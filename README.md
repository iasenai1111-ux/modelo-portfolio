# Modelo de portfólio no GitHub

Guia e modelos prontos para montar um portfólio de tecnologia do zero, mesmo sem experiência profissional.

## O que tem aqui

| Arquivo | Para quê |
|---|---|
| [`MODELO_PERFIL.md`](MODELO_PERFIL.md) | README do seu perfil (a página inicial do seu GitHub) |
| [`MODELO_PROJETO.md`](MODELO_PROJETO.md) | README de cada projeto |
| [`CHECKLIST.md`](CHECKLIST.md) | Conferência antes de divulgar o link |

## Passo a passo

1. **Crie o repositório do perfil.** Ele precisa ter exatamente o mesmo nome do seu usuário e ser público. O README dele aparece na sua página inicial.
2. **Copie o `MODELO_PERFIL.md`** para o `README.md` desse repositório e preencha.
3. **Publique seu primeiro projeto.** Pode ser um exercício de aula, desde que você tenha mudado algo: outro dataset, outra pergunta, uma melhoria.
4. **Use o `MODELO_PROJETO.md`** no README do projeto.
5. **Fixe os melhores.** No seu perfil, use *Customize your pins* para destacar até seis repositórios.
6. **Passe pelo `CHECKLIST.md`** e só então coloque o link no currículo e no LinkedIn.

## O que um recrutador procura

Quem avalia um portfólio costuma gastar poucos minutos nele. Nesse tempo, precisa encontrar:

- **Que problema** o projeto resolve
- **Como** você resolveu e por que escolheu esse caminho
- **O resultado**, de preferência com imagem ou número
- **Como rodar**, para conferir que funciona

Três projetos bem explicados valem mais do que vinte repositórios sem README.

## Erros comuns

- Repositório sem README, ou com o README padrão da ferramenta
- Nomes como `projeto1`, `teste`, `trabalho-final`
- Código copiado de tutorial sem nenhuma mudança
- Senhas, tokens ou chaves de API dentro do código (use variáveis de ambiente e `.gitignore`)
- Dados pessoais reais de outras pessoas nos datasets
